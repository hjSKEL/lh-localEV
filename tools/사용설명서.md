# 테스트 데이터 생성기 사용설명서

관제 화면 개발용 테스트 데이터를 만드는 도구 두 개.

## 1. OCPP 시뮬레이터 (`ocpp-simulator/`)

관제 화면에서 볼 다양한 충전 시나리오(정상충전/카드거절 등)를 실제 daemon 파이프라인을 통해 만드는 도구.

### 사전 조건
시뮬레이터가 흉내내는 충전기(`CP_ID-CS_ID`)와 인증카드(`idTag`)가 **DB에 이미 존재**해야 함. 없는 조합으로 돌리면 Authorize/StartTransaction이 실패함.

### 1) daemon 기동 (한 번만, 켜두고 계속 재사용)
```
cd localcsms/daemon/ocpp16-daemon
JAVA_HOME="C:\Program Files\Microsoft\jdk-17.0.19.10-hotspot" PATH="C:\Program Files\Microsoft\jdk-17.0.19.10-hotspot\bin:$PATH" \
  mvn spring-boot:run -Dspring-boot.run.arguments="0 localhost 8900"
```
- 인자는 `<sp level> <ip> <port>` — **공백 구분**(콤마 아님, 콤마로 주면 조용히 실패하고 바로 종료됨).
- `sp=0`은 "충전소 존재 여부만 확인" 모드라 비밀번호 없이 접속 가능(테스트용으로 제일 간단).

### 2) 시나리오 파일 작성
`ocpp-simulator/scenarios/xxx.json`:
```json
{
  "cpId": "223406", "csId": "01", "connectorId": 1,
  "sessions": [
    { "idTag": "카드번호", "meterStartWh": 0, "kwhPerTick": 500, "ticks": 4, "tickIntervalMs": 300 }
  ]
}
```
- `sessions` 배열 하나 = 카드 한 장으로 한 번 충전 시도.
- `idTag`가 `TB_CUCU002`에서 Accepted가 아니면(만료/정지/무효 카드) 그 세션은 Authorize에서 끝나고 트랜잭션은 안 만들어짐 — 실패 케이스도 그대로 재현됨.
- `meterStartWh`/`kwhPerTick`/`ticks`: 시작 계량값과 틱마다 늘어나는 전력량(Wh), 몇 번 보낼지.
- 최상위를 배열(`[{...}, {...}]`)로 주면 여러 충전기를 동시에 돌릴 수 있음.

### 3) 실행
```
cd ocpp-simulator
node simulate.js scenarios/lh-sample.json
```
콘솔에 Authorize 결과, transactionId, StopTransaction 결과가 그대로 찍힘. 결과는 `TB_RCRC001`(트랜잭션 이력), `TB_CHCS005`(커넥터 현재 상태)에 반영됨.

## 2. 백업 DB 복사 (`backup-db-copy/`)

일반적인 "물량" 데이터(수백~수천 건의 고객/충전기/이력)를 실제 운영 백업에서 가져와 익명화해 로컬에 채우는 도구.

```
cd backup-db-copy
node copy.js
```
- 접속정보/복사 건수는 `.env`에 있음(`COPY_LIMIT=500` = 테이블당 500건).
- 다시 실행해도 `INSERT IGNORE`라 중복 PK는 그냥 스킵됨 — 여러 번 돌려도 안전.
- `COPY_LIMIT` 값을 바꾸거나 지우면(전체 복사) 그 다음 실행부터 반영됨.
- 백업 DB와 로컬 DB는 스키마가 다를 수 있어(로컬이 LH용으로 축소됨), 로컬 테이블에 실제 있는 컬럼만 골라서 복사함. 백업에 없는 신규 테이블(`TB_ORCX001`, `TB_CUEV001`)은 자동 skip.

### 2-1) TB_CHCS005(커넥터 현재상태) 채우기
`copy.js`는 `TB_CHCS001`(커넥터)과 `TB_CHCS005`(현재상태)를 각각 독립적으로 잘라서 복사하기 때문에, 커넥터는 있는데 상태 행이 없는 경우가 생김(관제 화면에서 그 커넥터 상태가 비어 보임). `copy.js` 실행 후 아래를 한 번 더 돌려서 채운다.
```
node fill-chcs005.js
```
`TB_CHCS001`에는 있는데 `TB_CHCS005`가 없는 커넥터에 기본 상태(충전대기/`CHRS03`) 행을 생성함. 이미 채워진 커넥터는 건드리지 않으므로 여러 번 실행해도 안전.
